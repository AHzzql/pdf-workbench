# 登录与账户界面

## 入口与使用模式

工作台默认以游客身份直接使用。正式集成仅在原顶栏增加一个可选登录入口，登录与账户表单采用弹窗，不替换工作台首页或主布局。以下全页场景用于视觉参考，入口与弹窗结构见 `../../plans/2026-10-19-optional-account.md`。

## 视觉方向

| 方案           | 配色与结构                                                 | 适用取舍                                         |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| A · 工作台延续 | 蓝白配色，浅蓝文档展示区，白色表单；账户页沿用现有侧栏结构 | 与现有 PDF 工作台衔接直接，新增样式最少          |
| B · 纸感编辑室 | 暖白、灰绿、墨绿；衬线标题、小圆角、纸张层次               | 文档阅读特征更强，需统一账户区与工作台的配色边界 |
| C · 深色专注   | 深蓝文档展示区、浅色表单、蓝紫按钮；账户页采用深色侧栏     | 入口辨识度高，需维护深浅两套侧栏对比度           |

## 页面与交互

- 登录：邮箱、密码、密码可见性切换、注册入口、必填与邮箱格式校验。
- 注册：昵称、邮箱、密码、确认密码；密码不一致时提供表单错误。
- 账户资料：昵称编辑、只读登录邮箱、个人账户摘要、退出登录入口。
- 账户安全：当前密码、新密码、确认新密码；校验确认值与新旧密码差异。
- 原型工具栏：三个视觉方案、四个页面，以及正常、提交中、错误、空状态切换。
- 昵称提交采用文本渲染；密码不写入存储，校验通过后清空。所有表单仅在浏览器内校验，不发送网络请求。
- 原型账户使用示例昵称及 `example.com` 邮箱；侧栏文档工具为布局参考，不承担路由功能。

## 视觉与可访问性

正文复用项目现有字体栈；B 的展示标题增加本机宋体后备。间距以 4、8、12、16、24、32、48 px 为基准，标题采用 22–40 px，表单正文 12–16 px。移动端隐藏装饰文档区和工具侧栏，表单改单列，输入字号为 16 px。按钮采用原生控件，保留可见焦点环；错误采用 `role="alert"`，提交与保存反馈采用 `role="status"`，忙碌表单使用 `aria-busy`。状态用文字说明，不仅依赖颜色。

## 运行

`index.html`、`prototype.css` 与 `prototype.js` 为无外部依赖的静态文件，可直接打开 `index.html`，或由静态 HTTP 服务提供。地址片段采用 `#a/login`、`#b/register`、`#c/profile` 与 `#a/security` 等形式。界面原型独立于 `frontend/src` 与后端鉴权链路。

账户服务接入需定义邮箱唯一性、密码策略、会话有效期、退出失效、接口权限及资料持久化。第三方登录、邮箱验证码、密码找回、订阅计费与团队管理不在本原型页面范围。

## 原型验证

安装现有前端依赖后，在项目根目录执行 `node docs/ui/account/verify.cjs`。脚本启动临时本地服务并使用项目已有 Playwright，检查三套视觉、四个场景与六种宽度，以及表单校验、状态切换、焦点、昵称文本渲染和密码清理。结果与七张截图写入 `frontend/test-results/account-ui/`。版本内的界面截图位于 `previews/`。
