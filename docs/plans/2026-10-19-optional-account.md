# 游客模式与可选账户模块开发计划

## 目标与边界

PDF 工作台默认直接进入游客模式。首次访问仍打开原有文本提取工作台，不显示登录拦截、不自动弹出登录框。现有七组 PDF 工具和智能阅读的使用条件、页面布局、接口输入输出保持不变；登录不成为这些功能的使用前提。

原界面仅在顶栏右侧增加一个账户入口。游客显示“登录”，已登录时显示昵称与账户入口。登录、注册、资料设置及密码修改均通过该入口打开，不另建默认登录首页，不替换工作台侧栏、文档预览区与工具面板。关闭账户界面、退出账户或会话到期后，继续使用原工作台。

账户最小范围为邮箱注册、密码登录、查看当前账户、编辑昵称、修改密码和退出登录。账户功能不增加云端文档、个人文档列表、跨设备同步、会员、团队、后台管理、第三方登录、邮箱验证码或密码找回。现有本机 PDF 与智能阅读数据不自动归属或迁移到账户；账户不构成现有本机数据的多用户隔离边界。

## 页面与交互方案

### 1. 工作台入口

- 顶栏保留工具标题、已有说明与 API 文档链接，新增轻量“登录”按钮。
- 不显示强制注册提示，不占用文档预览区域，不改变七组工具的原有操作路径。
- 登录态探测异步执行，不阻塞文件选择、PDF 处理或智能阅读；账户服务失败时保留游客工作能力。
- 顶栏在窄屏保持入口可见，不能依赖 850 px 以下已隐藏的 `.sidebar-footer`。

### 2. 登录与注册

- 使用原生 `dialog` 承载账户面板，桌面表单约 440 px 宽，移动端使用视口内的单列表单。
- 登录字段为邮箱、密码，提供密码显隐、注册切换、关闭和“继续以游客使用”。
- 注册字段为昵称、邮箱、密码、确认密码；注册成功后切回登录，保留邮箱但清空密码。
- 打开、关闭、切换面板不销毁 `WorkbenchView`，保留当前文件、工具参数、处理结果与智能阅读状态。
- 提交中禁用重复提交；错误在表单内显示。登录成功后关闭面板，仍停留在当前工具。
- 关闭时清空密码；支持键盘操作、Escape、焦点限制及关闭后焦点返回入口。

### 3. 账户资料与安全

- 已登录入口打开同一账户面板，提供“个人资料”和“账户安全”两组内容。
- 资料包含可编辑昵称与只读登录邮箱，不增加头像上传和个人资料扩展字段。
- 修改密码需要当前密码、新密码及确认值，修改成功后使旧登录态失效并恢复游客状态。
- 退出仅清除当前账户会话，不清除当前 PDF、处理结果或智能阅读内容。
- 账户会话失效时关闭受保护表单或切换为可选登录界面，不跳离工作台、不清空文档。

### 4. 视觉范围

账户控件沿用现有字体、间距与蓝白色系。现有 A/B/C 静态页面作为账户视觉参考；正式界面采用工作台入口与弹窗结构，不采用独立全页登录首页。样式作用域限定在账户入口和面板内，避免修改全局 `nav`、`header`、`input` 等选择器影响现有工具。

## 技术设计

### 前端职责与文件

| 文件                                        | 计划职责                                 |
| ------------------------------------------- | ---------------------------------------- |
| `frontend/src/views/WorkbenchView.vue`      | 新增入口和面板挂载点，不重建工作台状态   |
| `frontend/src/components/AccountDialog.vue` | 登录、注册、资料、安全表单与弹窗生命周期 |
| `frontend/src/composables/useAccount.ts`    | 登录态恢复、账户请求状态与会话失效处理   |
| `frontend/src/api/account.ts`               | 独立账户请求封装，处理 CSRF 与账户错误   |
| `frontend/src/types/account.ts`             | 用户、会话及表单响应类型                 |
| `frontend/src/assets/account.css`           | 账户局部样式与窄屏适配                   |
| `frontend/src/components/AppIcon.vue`       | 复用已有图标，补充账户图标               |

保留 `frontend/src/router/index.ts` 的默认重定向与七组工具路由，不添加全局登录守卫。`api/pdf.ts`、`api/ai.ts` 不依赖账户状态，也不因账户接口返回 401 而改变原有行为。

### 后端职责与文件

- 在 `backend/src/main/java/cn/edu/pdfworkbench/auth/` 新增账户控制器、服务、参数与持久化职责。
- 在 `config/AccountSecurityConfig.java` 配置仅匹配 `/api/v1/account/**` 的安全链；注册、登录、会话查询和 CSRF 获取允许匿名访问，其余账户操作要求有效登录态。
- 保留 `/api/v1/pdf/**`、智能阅读、静态资源和 API 文档的现有访问方式，不增加账户认证和账户 CSRF 前提。
- 复用 Spring JDBC 与 H2 的既有技术栈；账户表和数据文件与智能阅读历史分开，不为账户引入 JPA、JWT 或外部数据库。
- `backend/pom.xml` 增加与现有 Spring Boot 版本匹配的 Spring Security 依赖；账户配置写入 `application.yml`，不写入凭据。
- 复用现有 `ApiException` 与统一异常响应结构，账户接口错误返回 JSON，不返回框架默认登录页面。

### 新增接口设计

以下为计划新增接口，不替换现有 PDF 与智能阅读接口。

| 方法与路径                      | 访问条件   | 输入与结果                                 |
| ------------------------------- | ---------- | ------------------------------------------ |
| `GET /api/v1/account/session`   | 游客或账户 | 游客返回未登录状态，账户返回当前昵称与邮箱 |
| `GET /api/v1/account/csrf`      | 游客或账户 | 返回账户写请求所需 CSRF 信息               |
| `POST /api/v1/account/register` | 游客       | 邮箱、昵称、密码；创建账户                 |
| `POST /api/v1/account/login`    | 游客       | 邮箱、密码；建立会话并返回账户资料         |
| `PATCH /api/v1/account/profile` | 当前账户   | 更新当前账户昵称，不接受外部账户 ID        |
| `POST /api/v1/account/password` | 当前账户   | 当前密码、新密码；完成修改并使旧登录态失效 |
| `POST /api/v1/account/logout`   | 游客或账户 | 结束当前会话，重复退出保持无副作用         |

采用服务端 Session 与 HttpOnly、SameSite Cookie；登录时更新会话标识，HTTPS 部署启用 Secure。密码使用框架提供的自适应散列，具体长度限制与编码器约束一致；密码、散列与会话标识不进入业务日志或账户响应。邮箱进行一致的规范化与数据库唯一性校验，查询使用参数绑定。账户写接口校验 CSRF，登录失败使用统一错误并限制尝试频率。密码变更后的旧会话失效覆盖同一账户已建立的会话。

安全链范围按 [Spring Security 请求匹配文档](https://docs.spring.io/spring-security/reference/servlet/configuration/java.html) 配置；账户写请求按 [Spring Security CSRF 文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html) 实施。实现时以项目实际解析到的依赖版本核验 API。

## 实施顺序

### 阶段一：收敛 UI

1. 在原工作台截图与布局上增加一个顶栏入口，制作游客默认、登录弹窗、注册弹窗和账户面板的预览。
2. 对比正常、提交中、失败与会话到期状态，检查桌面和窄屏布局。
3. 固定弹窗尺寸、入口位置、字段文案和账户局部样式，不改动工作台主布局。

### 阶段二：建立游客回归基线

1. 扩展 `frontend/tests/e2e/workbench.spec.ts`，覆盖无 Cookie 时直接进入七组工具。
2. 在 `backend/src/test/java/cn/edu/pdfworkbench/AccountApiTest.java` 增加账户接口访问测试；在现有 `PdfApiTest`、`AiApiTest` 增加匿名兼容断言。
3. 在账户服务不可用、无会话和会话到期场景下，验证已有 PDF 与智能阅读功能不依赖登录。

### 阶段三：账户服务

1. 先编写账户注册、登录、资料修改、密码修改和退出测试，再实现对应职责。
2. 验证重复邮箱并发注册、空白昵称、无效邮箱、错误密码、越界密码长度、CSRF 缺失、会话更新与旧会话失效。
3. 验证重启后账户记录仍存在，游客处理不依赖账户存储可用性。

### 阶段四：前端接入

1. 在 `frontend/tests/account.test.ts` 覆盖状态恢复、失败降级、资料更新和会话失效；在 `frontend/tests/account-dialog.test.ts` 覆盖表单与弹窗。
2. 实现账户请求封装和状态管理，将入口与面板接入 `WorkbenchView.vue`。
3. 在 `frontend/tests/e2e/account.spec.ts` 验证注册、登录、改名、改密、退出与继续游客使用闭环。
4. 验证面板开关和账户切换前后当前 PDF、工具参数、处理结果及阅读状态不被重置。

### 阶段五：验收与提交

- 执行 `npm --prefix frontend test`、`npm --prefix frontend run build`、`npm --prefix frontend run lint`。
- 在项目 Java/Maven 环境执行 `mvn -f backend/pom.xml test` 与打包。
- 执行工作台和账户浏览器测试；在模型服务配置齐备的环境独立执行真实智能阅读回归。
- 检查匿名 POST、下载、流式请求和停止重试，防止安全配置产生全局拦截或 CSRF 回归。
- 检查新增文案、账户数据边界、异常响应、敏感信息与 Git diff；将实际结果写入 `DEV_STATE.md` 后提交。

## 验收条件

1. 新访客直接看到原工作台，无登录跳转、强制弹窗或登录后解锁功能。
2. 游客能够按原有方式使用七组工具和智能阅读；原有业务异常行为保持不变。
3. 原界面仅新增一个账户入口，其他业务布局与操作流程不变。
4. 账户界面能够关闭，登录失败或账户服务故障不阻断游客处理。
5. 注册、登录、修改昵称、修改密码、退出与会话失效具有独立测试覆盖。
6. 退出和会话到期后保留当前工作台内容，仍可继续游客操作。
7. 账户身份不能读取或修改其他账户资料；账户信息不暗示本机文档具有新增的多用户隔离能力。
8. 账户存储不可用、会话失效或密码校验失败时返回明确错误，不关闭工作台，也不影响游客接口。
