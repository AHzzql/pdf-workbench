## Part A：English requirements specification / design

### 1. PDF Extractor Project

- **1.1 Introduction**：2–3 段，约 200–300 个英文单词，介绍问题、用户、范围和 Web 应用形态。
- **1.2 Key Feature List**：项目已实现功能的项目符号列表；FR8 可选附件提取不列为已实现。
- **1.3 Requirements Elicitation Work**：保留四个子节，不能合并为单一决策矩阵。
  - **1.3.1 Stakeholders**：终端用户、PDF/文档管理员、开发人员、系统管理员、管理敏感文档的组织、项目验收方；给出业务角色示例。
  - **1.3.2 User Needs Identified**：逐项覆盖模板的 10 个问题，改写为事实陈述，涵盖用户、PDF 类型/容量、单次输入、原件保护、保存位置、输出格式、加密输入、错误反馈与显示/导出。
  - **1.3.3 Requirements Questions**：第一张假设/澄清矩阵，记录原始功能歧义、问题、事实性答案或明确假设/约束。图片原始编码、转换失败、分辨率、资源去重与命名五个示例问题全部覆盖。
  - **1.3.4 Software Requirements Elicitation Questions**：第二张矩阵，逐项覆盖模板的 20 个问题。不得用第一张矩阵代替。

第二张矩阵包括主要用户、操作系统、PDF 版本、大小、密码、扫描件、表格成功条件、多栏顺序、图片格式、证书格式、签名材料存放、移除权限、验签失败、水印页范围、原件保护、输出格式、错误沟通、性能、安全和必选/可选范围。性能目标与实测结果分别标注来源；不将设计假设写成已有测试结论。

### 2. Functional Requirements (as DFDs & WNDs)

- **2.1 Introduction**：单独的 200–300 英文单词引言，不与 1.1 合并计算篇幅。
- **2.2 Functional Requirements (FRs) – Data-Flow-Diagram Modelling**：每组先有导入句，再给出 DFD；新增数据流在图后附一段解释。
  - **2.2.1 Text Extraction FR1 through to FR9 DFD**。
  - **2.2.2 Table Extraction FR10 and FR11 DFD**。
  - **2.2.3 Image Extract FR12 DFD**。
  - **2.2.4 PDF Encryption FR13 through to FR16 DFD**。
  - **2.2.5 Digital Signature FR17 through to FR19 DFD**。
  - 任务书另有文字/图片水印要求，作为 **2.2.6 Watermarking DFD** 补充，不改写 FR1–FR19 的含义。FR8、FR9 的可选性质明确；当前范围为不纳入 FR8、纳入 FR9。
- **2.3 Functional Requirements – Error Handling Common Use Package**：覆盖模板列出的 15 类情形，关联真实错误码/结果状态和用户可理解的英文反馈。100/110 是模板示例，不能替换既有 API 的稳定错误码；无内容、验签无效等业务结果与 HTTP 调用失败分别说明。
- **2.4 Functional Requirements – Window Navigation Diagram Prototype**：WND、界面原型图、状态/错误与保存路径，覆盖模板的 9 类最低界面职责。Swagger/OpenAPI 提供可交互接口说明及截图，WND 依据工作台实际导航绘制；两者以同一功能/操作对应，不用纯接口清单代替导航图。

详细 FR、NFR、范围规则和验收条件嵌入相应章节或作为必要附录，不继续以原有十章中文规格替代模板结构。详细架构、类设计、实现和测试执行材料归入 Part B。

## Part B：中文功能原型与交付材料

### 1. PDF Extractor Project

- **1.1 项目介绍**：中文 2–3 段。模板原文为 approximately 200–300 words；不将英文单词数直接等同于汉字数。
- **1.2 交付物 2：应用设计**。
  - **1.2.1 系统架构**：本机部署、进程/组件职责、数据流及必要模型，与实际代码一致。
  - **1.2.2 类／模块设计**：真实模块、类、主要接口和依赖，可配类图/模块图。
  - **1.2.3 界面设计、WND 与 Swagger 文档**：界面设计理由、导航、截图及 Swagger 文档。
- **1.3 交付物 3：应用软件**。
  - **1.3.1 可执行软件文件**：提供实际软件文件及运行依赖、配置入口、启动和访问说明。Web 应用可交付后端 JAR、前端构建文件和部署脚本，不将 .exe 视为模板明定格式。
- **1.4 交付物 4：测试**。
  - **1.4.1 JUnit 测试及执行记录**：至少五条完整、实际执行的测试记录，以表格关联用例、预期结果、实际结果、通过/失败和截图/输出文件证据，覆盖错误处理及边界条件。自动化测试总数不代替这些记录。
  - **1.4.2 可测量验收标准**：与 Part A 同一功能编号和业务边界对应，可采用“给定／当／那么”结构。
- **1.5 交付物 5：源码质量**：Java 不低于 17；当前目标字节码 Java 21，实际验证 JDK 25。提供源码，并使用模板的 Requirement / Implementation / Test Case / Evidence 四列，追踪到真实类/方法、用例与材料。
- **1.6 交付物 6：范围边界**：已实现功能、适用 PDF 特性、明确排除项及技术限制。
- **1.7 交付物 7：课堂演示**：随附 PPT，合计不超过 15 张幻灯片；课堂演示经历只有执行后才形成实际记录。

模板中的辅助开发说明落实于开发和 JUnit 测试工作，不作为 PDF 产品功能、验收项或独立过程章节。正式提交继续不扩展可选登录与助手模块章节。

## 最终交付组织

两份按模板编写的 Word 主文件为 Part A 与 Part B。Part B 同时附带：可运行的软件与资源、Java/前端源代码和 JUnit 源码、必要的本机部署材料、实际测试输出/截图、Swagger/OpenAPI 材料，以及不超过 15 页的演示文稿。压缩包名称、文件名和打包层次为交付组织方案，不作为模板明定格式；PDF 导出可用于阅读核验，不替代 Word 或软件本体。

交付包排除本机 .env.local、密码、私钥、真实签名材料、运行数据库和用户文档。证书类测试仅使用对应测试夹具；运行配置由初始化入口生成。
